DUTCH NATIONAL FLAG (THREE-WAY PARTITION) — LeetCode 75

When to recognize it
Use this pattern when an array has three categories and you must group them
in one pass, especially when the values are 0, 1, and 2. The key is to keep
three regions and shrink the unknown region as you scan.

Three pointers
- low: boundary after the region of 0s
- mid: current element being examined
- high: boundary before the region of 2s

At every step, maintain this invariant:
[0 ... low-1] are 0s
[low ... mid-1] are 1s
[mid ... high] are unknown
[high+1 ... end] are 2s

Java template
    int low = 0;
    int mid = 0;
    int high = nums.length - 1;

    while (mid <= high) {
        if (nums[mid] == 0) {
            swap(nums, low, mid);
            low++;
            mid++;
        } else if (nums[mid] == 1) {
            mid++;
        } else { // nums[mid] == 2
            swap(nums, mid, high);
            high--;
            // Do not advance mid: the swapped-in value is still unknown.
        }
    }

Why the pointer moves differ
- For 0: move it into the left region. The value swapped from low was already
  in the known 0-or-1 region, so advancing mid is safe.
- For 1: it already belongs in the middle region, so just advance mid.
- For 2: move it into the right region. The value coming from high has not been
  examined, so keep mid where it is and inspect that value next.

Dry run: [2, 0, 2, 1, 1, 0]
Start: low=0, mid=0, high=5
1. nums[mid]=2: swap with high -> [0, 0, 2, 1, 1, 2], high=4; inspect mid again
2. nums[mid]=0: swap low/mid -> [0, 0, 2, 1, 1, 2], low=1, mid=1
3. nums[mid]=0: swap low/mid -> [0, 0, 2, 1, 1, 2], low=2, mid=2
4. nums[mid]=2: swap with high -> [0, 0, 1, 1, 2, 2], high=3; inspect mid again
5. nums[mid]=1: mid=3
6. nums[mid]=1: mid=4; now mid > high, done

Complexity
- Time: O(n). Each iteration moves either mid or high, shrinking the unknown
  region; no element is repeatedly scanned.
- Auxiliary space: O(1). The swaps happen in the input array.

Common mistakes
- Advancing mid after swapping a 2: the incoming value from high is unexamined.
- Forgetting mid++ for a 0: if low == mid, this can loop forever.
- Using while (mid < high): the last unknown element may be skipped. Use mid <= high.
- Assuming every value is 0, 1, or 2 without checking the problem constraints.

Recall cue
“Left is 0, middle is 1, right is 2, and only mid through high is unknown.”
